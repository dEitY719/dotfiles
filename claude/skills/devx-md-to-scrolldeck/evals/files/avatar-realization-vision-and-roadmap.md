# 오늘 기록하는 업무가, 내일 일하는 아바타가 됩니다

> 업무 지식의 자산화에서 클라우드 자율 Agent까지 — 아바타 현실화 비전과 로드맵

## 이 문서를 읽는 분께

아바타는 언젠가 완성된 AI가 우리에게 주어지는 미래의 개념이 아닙니다. 우리가 오늘 작성하는
책임·역할·업무에서 시작해, 실제 AI가 이해하고 수행할 수 있는 업무 파트너로 점차 현실화됩니다.

이 변화는 기술 조직이 시스템을 개발하고 임직원이 기다리는 방식으로 완성되지 않습니다. 임직원이
자신의 업무 지식을 구조화하고, 리더가 이를 안전한 AX 활동으로 지원하며, 플랫폼 조직이 실행·보안·승인
기반을 연결할 때 비로소 아바타가 일할 수 있게 됩니다.

따라서 이 문서는 투자를 승인받기 위한 제안서가 아닙니다. 임직원과 임원진이 같은 비전을 갖고,
각자의 위치에서 아바타의 현실화에 참여하기 위한 공동 안내서입니다.

## 한눈에 보는 아바타 현실화

| 시점               | 아바타의 모습                      | 지금 작성한 자산의 활용                             | 사람의 역할                      |
| ------------------ | ---------------------------------- | --------------------------------------------------- | -------------------------------- |
| **지금 사용 가능** | 업무를 이해하는 AI 작업 파트너     | Claude Code용 Agent·Skill 번들, 인수인계, 업무 검색 | 구체적으로 지시하고 결과 검토    |
| **3개월 제안**     | 하나의 Task를 실행하는 Cloud Agent | Task Runner의 실행 명세                             | 실행 입력 제공, 결과 승인        |
| **6개월 제안**     | 반복 업무를 제한적으로 자율 수행   | 스케줄·이벤트·업무 시스템 연결                      | 예외와 중요 결정 관리            |
| **1년 비전**       | 여러 역할을 조율하며 목표를 수행   | 조직의 Agent 업무 운영체제                          | 아바타 팀 지휘, 새로운 가치 구상 |

사람의 일하는 방식도 함께 진화합니다.

```text
직접 한다
→ 맡기고 검토한다
→ 여러 아바타를 지휘한다
→ 새로운 가치를 구상한다
```

## 1. AI 도구는 많아졌지만, AI는 아직 우리의 업무를 모릅니다

AI 모델과 Skill, MCP, Agent는 빠르게 발전하고 있습니다. 하지만 도구가 많아진 것만으로는 실제 업무를
맡길 수 없습니다. AI는 다음과 같은 조직의 업무 맥락을 스스로 알지 못합니다.

- 누가 어떤 결과를 책임지는가?
- 그 책임을 완수하려면 어떤 역할이 필요한가?
- 업무는 언제 시작되고 무엇을 입력받는가?
- 어떤 절차와 도구를 사용해야 하는가?
- 무엇이 완성된 결과이며 누가 검토해야 하는가?

이 정보는 대부분 구성원의 머릿속, 개인 문서, 메일, 메신저, 회의 기록에 흩어져 있습니다. 그래서 AI를
사용할 때마다 자신의 일을 처음부터 다시 설명해야 하고, 좋은 활용법도 개인 경험에 머무릅니다.

> 지금 우리에게 부족한 것은 또 하나의 AI 도구가 아니라, AI가 일할 수 있는 구조화된 업무 맥락입니다.

## 2. 아바타는 사람의 복제가 아니라 가상의 업무 파트너입니다

아바타는 하나 이상의 역할을 가지고 주어진 책임을 완수하는 가상의 업무 파트너입니다.

아바타는 사람의 외모나 성격을 복제하지 않습니다. 조직도나 직급을 디지털로 옮기는 것도 아닙니다.
사람이 실제로 맡은 일을 AI와 협업할 수 있는 구조로 표현합니다.

| 아바타가 아닌 것                   | 아바타인 것                                   |
| ---------------------------------- | --------------------------------------------- |
| 사람을 평가하기 위한 디지털 프로필 | 업무를 설명·위임·재사용하기 위한 파트너       |
| 기존 직무·직급 체계의 복제         | 실제 수행하는 책임과 업무의 구조화            |
| 모든 일을 대신하는 만능 AI         | 명확한 책임과 권한 안에서 일하는 Agent의 기반 |
| 기술이 완성된 뒤 도입하는 결과물   | 지금 업무를 기록하는 순간부터 쌓이는 자산     |

아바타의 목적은 사람을 대체하는 것이 아닙니다. 반복적인 실행을 아바타에 맡기고, 사람은 결과 검토,
예외 판단, 관계 조정, 전략과 새로운 가치 설계에 더 집중하도록 일하는 방식을 바꾸는 것입니다.

## 3. 책임·역할·업무·Skill이 아바타를 현실화합니다

아바타는 `Avatar Card → Avatar Role → Avatar Task → Skill`의 구조로 구체화됩니다.

### Avatar Card — 무엇을 책임지는가

아바타 카드는 하나의 분명한 책임을 가진 업무 파트너 프로필입니다.

예를 들어 `마켓 인텔리전스` 카드의 책임은 다음과 같습니다.

> 우리 부서가 매주 경쟁사 핵심 변화를 놓치지 않도록 찾아 요약·전달한다.

한 사람이 업무 맥락에 따라 여러 카드를 만들 수 있습니다. 개인의 직무 전체를 하나의 거대한 카드로
만들기보다, 책임과 결과가 분명한 단위로 나누는 것이 좋습니다.

### Avatar Role — 어떤 전문 역할로 일하는가

역할은 카드의 책임을 완수하기 위해 필요한 전문 작업자의 모습입니다.

`마켓 인텔리전스`에는 다음 역할이 필요할 수 있습니다.

- **정보 검색가**: 지정된 출처에서 경쟁사 자료를 찾고 정리합니다.
- **요약 보고자**: 수집한 자료를 의사결정용 보고서로 만듭니다.

잘 정의한 역할은 여러 카드에서 재사용할 수 있습니다. 예를 들어 `요약 보고자` 역할은 시장 조사,
고객 VOC, 기술 동향, 프로젝트 주간 보고 카드에서 함께 활용할 수 있습니다.

### Avatar Task — 실제로 무엇을 수행하는가

업무는 역할이 실행하는 구체적인 업무 지식 단위입니다. 업무에는 언제 시작하고 무엇을 입력받아 어떤
산출물을 만드는지가 드러나야 합니다.

예를 들면 다음과 같습니다.

- 경쟁사 기사·릴리스 수집
- 중복 URL 제거와 출처 정리
- 주간 동향 3줄 요약

`메일 보내기`, `Jira 상태 변경`, `git diff 확인`처럼 단일 클릭이나 명령에 가까운 행동은 별도 Task가
아니라 Task 안의 절차로 작성합니다.

### Skill — 실제로 어떻게 수행하는가

Skill은 Agent가 업무를 수행할 때 사용하는 실행 도구이자 매뉴얼입니다.

- 웹 자료 수집
- 중복 제거와 분류
- 변경 내용 요약
- 보고서 초안 작성
- 코드 리뷰

모든 업무가 처음부터 Skill을 가질 필요는 없습니다. 아직 자동화할 수 없는 절차, 외부 소프트웨어,
사내 시스템, H/W 장비, 사람의 판단은 Task의 설명에 기록합니다. 이 기록은 향후 새로운 Skill과
자동화 후보를 발견하는 근거가 됩니다.

## 4. 지금 작성하는 정보는 미래 Agent의 설정값입니다

현재의 아바타 정보는 미래를 설명하기 위한 참고 문서가 아닙니다. 이미 AI가 읽을 수 있는 실행 지침으로
변환할 수 있으며, 향후 클라우드 실행 환경에서도 같은 구조를 사용할 수 있습니다.

| 지금 작성하는 자산 | 현재의 실제 구현체           | 향후 실행 환경의 의미               |
| ------------------ | ---------------------------- | ----------------------------------- |
| Card의 책임        | `AGENTS.md`의 목표와 책임    | Agent가 지속적으로 관리할 목표      |
| Role               | `.claude/agents/<role>.md`   | 역할별 전문 실행 Agent              |
| Task               | `context`와 `text` 실행 지침 | 입력·출력·완료 조건을 가진 실행 Job |
| 연결 Skill         | `.claude/skills/<skill>/`    | Task Runner가 호출하는 실행 능력    |
| 공동 관리자        | 업무 지식 공동 편집자        | 결과 승인자·예외 책임자             |
| 공개 범위          | 개인·팀·전체 공유 정책       | 실행 정보와 결과의 접근 경계        |

여기서 Card 자체가 프로그램처럼 직접 실행되는 것은 아닙니다. Card·Role·Task는 업무 정의이고,
Exporter나 Task Runner가 AI 모델, Skill, 데이터, 권한을 연결하면 실행 가능한 아바타가 됩니다.

> 기술과 Agent 제품이 바뀌어도 책임·역할·업무로 구조화한 지식은 계속 재사용할 수 있습니다.

## 5. 지금 사용할 수 있는 아바타 활용 방법

### 5.1 AI와 대화하며 아바타 초안을 만들 수 있습니다

아바타 만들기에서는 평소 하는 일을 자연어로 설명하고 Card·Role·Task 초안을 만들거나, 기존 카드를
불러와 보완할 수 있습니다. AI가 제안한 내용과 Skill은 적용 전에 사람이 검토합니다.

예를 들면 다음처럼 시작할 수 있습니다.

> 매주 경쟁사 뉴스와 제품 발표를 찾아 핵심 변화만 정리해 팀에 공유합니다.

AI는 이 설명을 바탕으로 정보 검색가와 요약 보고자 역할, 자료 수집과 주간 요약 업무를 제안합니다.

### 5.2 팀의 역할과 업무를 검색하고 재사용할 수 있습니다

아바타 둘러보기에서는 팀의 Card·Role·Task를 검색할 수 있습니다. 이미 존재하는 역할과 업무를 새로
복사하지 않고 자신의 카드에 연결하면, 팀의 업무 지식이 공통 자산으로 발전합니다.

이 정보는 다음과 같은 질문에도 답합니다.

- 우리 팀에 어떤 책임과 업무가 존재하는가?
- 인수인계가 필요한 핵심 업무는 무엇인가?
- 설명이 비어 있거나 다른 항목과 연결되지 않은 업무는 무엇인가?
- 여러 사람이 반복하는 공통 업무는 무엇인가?
- 아직 적절한 Skill이 없는 자동화 후보는 무엇인가?

### 5.3 아바타 카드를 Claude Code용 Agent 번들로 내보낼 수 있습니다

**지금 사용 가능 — 실험 기능**

개인 실험실에서 `아바타 내보내기`를 활성화하면 아바타 카드를 Claude Code 서브에이전트 번들 ZIP으로
내보낼 수 있습니다.

```text
아바타 카드 작성
→ 역할·업무·Skill 연결
→ 카드 내보내기
→ 작업할 프로젝트에 ZIP 해제
→ Claude Code에서 역할별 Agent와 Skill 사용
→ 이번 실행의 자료와 요구사항 전달
→ 결과 검토
```

번들에는 다음과 같은 파일이 생성됩니다.

```text
AGENTS.md
.claude/agents/정보-검색가.md
.claude/agents/요약-보고자.md
.claude/skills/web-collector/...
.claude/skills/report-writer/...
```

- `AGENTS.md`에는 카드의 이름, 책임, 역할 목록이 들어갑니다.
- `.claude/agents/`에는 역할별 설명과 수행할 Task가 들어갑니다.
- `.claude/skills/`에는 연결된 Skill의 실행 파일이 포함됩니다.
- 파일을 포함할 수 없는 Skill은 설치할 위치나 출처를 안내합니다.

예를 들어 Claude Code에 다음과 같이 지시할 수 있습니다.

```text
마켓 인텔리전스 아바타의 '요약 보고자' 역할로 작업해 줘.

실행 업무: 주간 동향 3줄 요약
입력: 이번 주 수집 기사 목록과 첨부한 경쟁사 공시
산출물:
- 경쟁사별 핵심 변화 3줄
- 중요도와 판단 근거
- 원문 링크
- 다음 주 확인할 항목

외부 전송은 하지 말고 초안만 만들어 줘.
```

현재는 실행할 자료와 구체적인 요청을 사람이 제공하며, 결과 검토와 외부 반영도 사람이 담당합니다.
그럼에도 매번 역할과 절차를 처음부터 설명하지 않고, 아바타에 축적한 업무 지식과 Skill을 바로 사용할
수 있다는 의미가 있습니다.

### 5.4 Agent API로 아바타 정보를 읽을 수 있습니다

외부 Agent는 사용자 API 키와 권한 범위 안에서 Card·Role·Task 정보를 조회할 수 있습니다.

```text
GET /api/v1/agent/avatars/cards
GET /api/v1/agent/avatars/roles
GET /api/v1/agent/avatars/tasks
GET /api/v1/agent/avatars/tasks/{task_id}
```

이를 이용하면 Claude Code 외의 Agent나 사내 AI 서비스도 최신 업무 정의를 읽어 프롬프트와 실행 계획을
구성할 수 있습니다.

### 5.5 지금 당장 얻는 네 가지 가치

1. **AI 업무 위임**: 반복 설명 없이 책임·역할·업무·Skill을 AI에 전달합니다.
2. **인수인계와 온보딩**: 동료가 실제 업무와 사용하는 도구·산출물을 빠르게 이해합니다.
3. **팀 표준화와 재사용**: 잘 만든 Role과 Task를 여러 카드에서 공동으로 사용합니다.
4. **자동화 후보 발굴**: 반복되지만 Skill이 없는 Task를 다음 개발 후보로 발견합니다.

## 6. 현재 아바타가 아직 하지 못하는 일

현재 구현과 미래 비전을 혼동해서는 안 됩니다. Agent Factory 안에서 아바타 Task를 눌러 클라우드에서
실행하는 Task Runner는 아직 준비되지 않았습니다.

현재 추가로 필요한 기능은 다음과 같습니다.

- Task 실행 버튼과 실행 입력 화면
- 클라우드 AI 런타임
- 예약·이벤트 기반 실행
- Skill·MCP·외부 업무 시스템 호출
- 실행 상태·비용·결과 저장
- 결과 검증과 승인·반려
- 재시도·타임아웃·중복 실행 방지
- 권한·자격증명·감사 로그

이 경계를 명확히 하는 이유는 비전을 축소하기 위해서가 아닙니다. 이미 보유한 자산과 다음에 만들어야 할
실행 기반을 정확히 구분해야 현실적인 순서로 고도화할 수 있기 때문입니다.

## 7. 3개월: 하나의 Task를 클라우드에서 실행합니다

**3개월 제안 — Task Runner MVP**

첫 단계의 목표는 아바타 전체가 복잡한 프로젝트를 자율 수행하는 것이 아닙니다. 입력과 산출물이 분명한
하나의 Task를 안전하게 실행하는 것입니다.

```text
[주간 동향 3줄 요약] 실행
        ↓
실행 입력 제공
- 대상 기간
- 수집 자료
- 보고 대상
        ↓
연결 Skill과 AI 실행
        ↓
결과 미리보기
        ↓
사람의 승인 또는 반려
        ↓
실행 이력 저장
```

### Task Runner MVP의 범위

- 하나의 Task를 사용자가 수동 실행
- 실행 시점의 입력값과 자료 제공
- Task에 연결된 Skill 호출
- 결과물 미리보기
- 승인·반려와 수정 요청
- 실행 상태·소요 시간·비용·결과 기록

### 3개월 뒤 달라지는 점

지금은 아바타 정보를 AI 환경으로 내보내 사람이 대화를 시작합니다. Task Runner가 준비되면 등록된 Task
자체가 실행 진입점이 됩니다.

```text
업무를 설명하는 아바타
→ 실제 결과를 만드는 아바타
```

사람은 계속 실행을 시작하고 결과를 검토하지만, 실행 환경을 준비하고 업무 지침을 전달하는 과정이 크게
줄어듭니다.

## 8. 6개월: 반복 업무를 제한된 범위에서 자율 수행합니다

**6개월 제안 — Human-in-the-loop Automation**

Task Runner가 안정화되면 반복 업무에 스케줄과 이벤트를 연결할 수 있습니다.

```text
매일 09:00 경쟁사 기사 수집
→ 중복 제거와 중요도 분류
→ 금요일 주간 보고서 초안 작성
→ 담당자에게 승인 요청
→ 승인된 결과만 게시
```

### 필요한 실행 기반

- 스케줄, 웹훅, 업무 이벤트 트리거
- 사내 데이터, MCP, 외부 업무 시스템 연결
- 결과 형식과 완료 조건 검증
- 실패 재시도, 타임아웃, 중복 실행 방지
- 저위험 결과의 자동 반영
- 메일 발송, 데이터 변경 등 중요 행동의 승인
- 사용 근거, 품질, 비용을 보는 운영 대시보드

### 자율성의 원칙

아바타의 자율성은 모든 권한을 넘겨주는 것이 아닙니다. 업무 위험도에 따라 사람의 개입 수준을 다르게
설계합니다.

| 업무 수준           | 실행 방식                | 예시                         |
| ------------------- | ------------------------ | ---------------------------- |
| 정보 조회·초안 작성 | 자동 실행 후 결과 제공   | 자료 수집, 요약 초안         |
| 내부 데이터 갱신    | 실행 전후 검증 또는 승인 | Jira 상태 변경, 보고서 게시  |
| 외부 발송·삭제·결제 | 반드시 명시적 승인       | 고객 메일, 데이터 삭제, 구매 |

> 자율성은 무제한 권한이 아니라, 명확한 책임과 정책 안에서 안전하게 확대됩니다.

## 9. 1년: 여러 역할이 협업하며 목표를 수행합니다

**1년 비전 — Goal-driven Avatar Runtime**

Agent가 충분히 고도화되면 아바타는 개별 Task 실행을 넘어 카드의 책임과 목표를 기준으로 여러 역할을
조율할 수 있습니다.

```text
목표: 경쟁사 핵심 변화를 놓치지 않는다
        ↓
정보 검색가
자료 수집·출처 검증
        ↓
분석가
변화와 사업 영향 분석
        ↓
요약 보고자
의사결정용 보고서 작성
        ↓
사람
방향 설정·중요 결정·최종 책임
```

### 고도화된 아바타가 할 수 있는 일

- 목표를 달성하는 데 필요한 Task 계획
- 여러 Role과 Agent 사이의 업무 분배
- 과거 실행 결과와 장기 상태 활용
- 진행 상황과 의존성 관리
- 예외 감지와 담당자 에스컬레이션
- 새로운 문제와 기회 제안
- Role·Task·Skill 개선안 제안

예를 들어 기존 감시 대상이 아닌 신규 경쟁사의 움직임이 반복적으로 발견되면, 아바타가 관찰 목록 추가와
별도 분석 Task의 필요성을 제안할 수 있습니다. 사람은 그 제안의 전략적 의미를 판단하고 목표와 정책을
조정합니다.

1년 뒤에도 사람의 책임이 사라지는 것은 아닙니다. 사람은 아바타가 추구할 목표, 허용된 행동, 승인 기준,
예외 처리 방향을 정하고 최종적인 조직의 책임을 집니다.

## 10. 오늘 작성한 자산은 시간이 지날수록 가치가 커집니다

```text
오늘
개인의 업무 설명과 노하우

→ 3개월
AI가 실행할 수 있는 업무 명세

→ 6개월
팀이 재사용하는 자동화 자산

→ 1년
조직의 Agent 업무 운영체제
```

### 기술이 바뀌어도 남는 업무 자산

AI 모델, Agent 제품, 실행 플랫폼은 계속 바뀔 것입니다. 그러나 다음 정보는 특정 기술에 종속되지 않습니다.

- 우리가 어떤 결과를 책임지는가
- 그 책임을 완수하기 위해 어떤 역할이 필요한가
- 업무는 언제 시작되고 무엇을 산출하는가
- 어떤 지식과 도구가 필요한가
- 누가 결과를 검토하고 예외를 책임지는가

이 때문에 지금 작성한 Card·Role·Task는 Claude Code뿐 아니라 향후의 사내 Agent, 클라우드 Task Runner,
다른 AI 플랫폼에서도 사용할 수 있습니다.

### 조직이 얻게 되는 업무 지도

아바타 정보가 쌓이면 조직은 다음을 이해할 수 있습니다.

- 팀별로 반복되는 수동 업무
- 여러 조직이 공통으로 수행하는 업무
- 특정 구성원에게만 의존하는 핵심 지식
- 수요가 높지만 아직 존재하지 않는 Skill
- 자동화 가치가 높은 Task
- 사람의 승인과 책임이 반드시 필요한 업무

이 정보는 인사평가 자료가 아니라 AX 우선순위와 공통 자산을 결정하는 업무 지도입니다.

### 재사용이 만드는 복리 효과

한 사람이 만든 좋은 Task를 다른 Role과 Card가 재사용하고, 그 Task에 연결된 Skill이 개선되면 모든
사용처가 함께 혜택을 얻습니다.

```text
개인의 업무 기록
→ 팀의 표준 Task
→ 여러 카드에서 재사용
→ 공통 Skill 개선
→ 조직 전체의 실행 품질 향상
```

## 11. 아바타 고도화는 모두가 함께 만드는 변화입니다

### 구성원의 역할

- 자신이 실제로 수행하는 핵심 업무 카드 1개를 작성합니다.
- Task의 시작 조건, 입력, 절차, 산출물을 기록합니다.
- 이미 존재하는 Role·Task·Skill을 찾아 재사용합니다.
- AI 또는 동료에게 업무를 맡겨 보고 부족한 설명을 보완합니다.
- 필요한 Skill과 실행 과정의 문제점을 공유합니다.

### 리더의 역할

- 구성원이 카드를 작성하고 팀에서 검토할 시간을 확보합니다.
- 중복 Role·Task를 정리하고 팀의 공통 자산으로 발전시킵니다.
- 아바타 활동을 개인 평가가 아닌 업무 혁신과 지식 자산화 활동으로 보호합니다.
- 부서 사이의 재사용과 파일럿 확산을 지원합니다.
- 사람이 반드시 책임져야 할 판단과 승인 경계를 정의합니다.

### 플랫폼 조직의 역할

- Skill, MCP, Task Runner, 클라우드 실행 환경을 제공합니다.
- 권한, 자격증명, 승인, 감사, 비용, 품질 관측 체계를 구축합니다.
- 현장의 반복 업무와 불편을 고도화 우선순위에 반영합니다.
- 특정 Agent 제품에 종속되지 않는 업무 자산 구조를 유지합니다.

> 플랫폼이 실행 능력을 만들고 임직원이 업무 지식을 채울 때 아바타가 완성됩니다.

## 12. 우리가 지금 시작해야 할 한 가지

모든 업무를 한 번에 완벽하게 작성할 필요는 없습니다. 각 구성원이 반복적으로 수행하거나 인수인계가
필요한 핵심 업무 카드 1개부터 시작합니다.

### 작성 순서

1. **하는 일을 먼저 적습니다.** 동사와 산출물이 드러나는 5~10개 업무를 나열합니다.
2. **비슷한 업무를 역할로 묶습니다.** 보통 카드 하나에 2~4개 역할이면 충분합니다.
3. **전체 책임을 한 문장으로 정의합니다.** 어떤 결과를 책임지는 파트너인지 적습니다.
4. **기존 자산을 찾아 연결합니다.** Role·Task를 복사하기보다 재사용합니다.
5. **Skill과 다른 도구를 기록합니다.** Skill은 연결하고, 나머지 절차·시스템·장비는 설명에 적습니다.
6. **팀에서 함께 검토합니다.** 다른 사람이 이해하고 수행할 수 있는지 확인합니다.
7. **실제로 사용하고 개선합니다.** AI 내보내기, 인수인계, 협업에 사용하면서 부족한 내용을 고칩니다.

### 좋은 Task를 만드는 확인 질문

- 언제 이 업무를 시작하는가?
- 어떤 자료와 정보가 필요한가?
- 어떤 절차와 도구를 사용하는가?
- 최종 산출물은 무엇인가?
- 완료 여부를 어떻게 판단하는가?
- AI가 수행할 부분과 사람이 판단할 부분은 어디인가?
- 결과를 검토하거나 예외를 책임질 사람은 누구인가?

## 13. 운영 원칙과 안전장치

아바타는 실제 업무와 조직의 지식을 다루므로 다음 원칙을 지켜야 합니다.

1. **인사평가의 단독 근거로 사용하지 않습니다.** 목적은 업무 구조화와 AX입니다.
2. **필요한 범위에서만 정보를 공유합니다.** 비밀·자격증명·개인정보·고객 원문을 넣지 않습니다.
3. **위험한 행동에는 사람의 승인을 둡니다.** 외부 발송·삭제·결제·중요 데이터 변경은 자동화 범위를
   제한합니다.
4. **아바타의 행동을 기록합니다.** 실행 입력, 사용 도구, 결과, 승인, 오류를 추적할 수 있어야 합니다.
5. **사람이 최종 책임을 가집니다.** 아바타는 책임 있는 사람의 판단을 돕고 실행 부담을 줄이는 파트너입니다.

성과는 카드 개수나 개인별 AI 사용량이 아니라 다음과 같은 조직적 효과로 확인해야 합니다.

- 재사용되는 Role·Task 비율
- Task와 Skill의 연결 및 실제 활용률
- 인수인계와 업무 착수에 걸리는 시간 감소
- 반복 업무에 투입되는 시간 감소
- 자동 생성 결과의 승인·수정 비율
- 새롭게 발견한 공통 Skill과 자동화 후보

## 맺음말

아바타의 미래는 완성된 기술이 도착하는 날 시작되지 않습니다.

오늘 우리가 자신의 일을 Card·Role·Task로 구조화하면, 그 정보는 지금 바로 AI 업무 지시와 인수인계에
사용됩니다. Task Runner가 준비되면 같은 정보가 실행 명세가 되고, 스케줄과 업무 시스템이 연결되면
반복 업무를 수행하는 기반이 됩니다. Agent가 충분히 고도화된 뒤에는 여러 역할과 업무를 조율하는 조직의
업무 운영체제로 발전할 수 있습니다.

> 오늘 작성하는 아바타 카드는 미래를 설명하는 문서가 아닙니다. 미래의 Agent가 실제로 일하기 위해
> 필요한 첫 번째 실행 자산입니다.

우리가 지금 시작할 일은 분명합니다.

> **각 구성원이 핵심 업무 카드 1개를 작성하고, 팀에서 함께 검토합니다.**
