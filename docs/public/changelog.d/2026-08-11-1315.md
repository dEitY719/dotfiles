- 변경: **`gh:pr` 이 upstream 이 *다른 이름의* 브랜치를 가리키는 상태(`@{u}` ≠ `origin/<현재 브랜치>`)를 push 정책 표의 독립 행으로 인식 — 이제 항상 `git push -u origin HEAD` 로 재페어링한다. 종전 3행 표에는 이 상태에 맞는 행이 없어 2행("upstream 존재 · ahead · divergence 없음")으로 떨어졌고, 그 처방인 맨 `git push` 는 `push.default=upstream` 에서 피처 브랜치의 커밋을 upstream 브랜치(보통 `main`)에 PR·리뷰 없이 그대로 올려버렸다(실측: `feature -> main`, git 2.43.0/Linux). 기본값 `simple` 에서는 대신 `fatal: The upstream branch ... does not match` 로 중단됐다. 이는 드문 오설정이 아니라 `git worktree add ... -b <branch>` 를 `origin/main` 에서 시작할 때의 정상 귀결이다(`branch.autoSetupMerge` 가 첫 `-u` push 전까지 시작점을 upstream 으로 잡는다). 이 상태에서는 `git status` 의 ahead/behind 가 base 기준으로 계산되므로 mispair 판정이 divergence 판정보다 먼저 실행된다. 알려진 트레이드오프: 의도적으로 다른 이름의 원격 브랜치를 추적하던 경우(`fix` → `origin/hotfix-2026-08`) 기존 추적 대상 대신 동명의 새 원격 브랜치가 생긴다 — `gh:pr` 의 역할이 "현재 브랜치로 PR 을 연다" 이므로 수용한다 (#1315)**
- 변경: **`gh:pr` 이 base 브랜치(보통 로컬 `main`) 위에서 시작된 세션을 자동 복구 — 종전에는 "피처 브랜치를 만들어 달라" 하고 멈췄지만, 이제 로컬 전용 커밋을 새 브랜치로 옮기고 진행한다. 브랜치 이름은 이 저장소의 커밋 제목이 한글이라 slugify 가 빈/깨진 결과를 내므로 ASCII 접두사만 사용한다: 이슈 번호가 있으면 `<type>/issue-<N>`, 없으면 `<type>/<YYYYMMDD>-<short-sha>`(둘 다 결정적 — `date +%s`/난수 없음). 잊기 쉬운 필수 후속 단계인 로컬 base 되감기(`git branch -f "$BASE_BRANCH" "origin/$BASE_BRANCH"`)를 함께 수행하되, `git rev-list origin/$BASE..$BASE` 가 옮겨간 커밋 집합과 정확히 일치할 때만 자동 실행하고 아니면 경고만 남긴다. 커밋이 이미 `origin/$BASE` 에 올라가 있으면 PR 가능한 상태가 아니므로 종전대로 정지한다. 되감긴 커밋은 로컬 전용이라 `reflog` 로 복구 가능하며 복구 힌트 1줄을 출력한다. 새로 만든 브랜치는 upstream 이 없으므로 위 F-1 표의 1행(`git push -u origin HEAD`)으로 자연히 착지한다. base 브랜치의 미커밋 변경(dirty worktree)은 범위 밖 — 기존 "빈 범위 → PR 할 것 없음" 조건이 덮으며 커밋은 `gh:commit` 의 몫이다 (#1315)**
