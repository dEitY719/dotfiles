- 변경: **`shell-common/tools/custom/issue_watcher_cron.sh` 의 tick 이 부트스트랩하는 herdr pane 이 이제 `claude-yolo` 와 동일한 조건으로 claude 를 띄운다 — 무인 cron tick 이 권한 승인 프롬프트에서 멈추던 문제 해결. herdr 의 `--kind` enum 에는 `claude-yolo` 가 없고 외부 도구라 확장할 수 없으므로, `--kind claude` 는 그대로 두고 `claude_yolo()` 의 두 효과만 기존 herdr 호출에 인자로 재현했다: `herdr agent start ... -- --dangerously-skip-permissions`(pane 통과 인자)와 `herdr workspace create ... --env CLAUDE_CONFIG_DIR=<계정 디렉토리>`. 계정 해석은 `claude_yolo()` 와 같은 SSOT 를 재사용한다(그 함수 자체는 수정하지 않음) — `~/.dotfiles-setup-mode` 가 `internal` 이면 `$HOME/.claude`, 아니면 `_claude_resolve_account "${CLAUDE_DEFAULT_ACCOUNT:-personal}"`. 알 수 없는 계정이거나 해석된 디렉토리가 없으면 herdr 를 건드리기 전에 명확한 에러와 함께 fail-fast 한다(HOME 자체가 없는 bare cron 환경은 예외로, 경고 후 `--env` 없이 종전대로 진행). 부수 수정: `exec 9>"$LOCK" 2>/dev/null` 이 `2>/dev/null` 까지 영구 적용해 락 획득 이후의 모든 `ux_error` 를 cron 로그에서 통째로 삼키던 버그를 `{ exec 9>"$LOCK"; } 2>/dev/null` 로 고쳤다. 상태 파일 스키마와 single-instance 락 동작은 변경 없음 (#1393)**
