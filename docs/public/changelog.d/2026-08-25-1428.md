- 변경: **`/skill:create` 의 description 최적화 루프(`python -m scripts.run_loop`)가 이제 하네스 고장을 `[ERROR]` 로 구분하고 원인 stderr 를 함께 출력한다. PR #1422(#1412) 가 도입한 F-2/F-3 은 `run_eval.py` 의 `main()` 에만 배선돼 있었는데, `run_loop.py` 는 `run_eval()` 을 직접 호출하므로 문서가 최적화 진입점으로 지정한 경로에서는 `claude -p` 가 100% 죽어 있어도 평범한 `[FAIL] rate=0/2` 만 찍혔다 — 분모 `2` 는 실행 건수가 아니라 시도 횟수였고, F-2 가 없애려던 착시(하네스 고장을 description 결함으로 오독)가 그대로 남아 있었다. 이번 수정은 `[ERROR]` 판정 규칙·`usable_runs()` 분모·stderr 발췌를 `scripts/utils.py` 의 `format_result_lines()` 한 곳으로 올려 두 진입점이 공유하게 한다 — 규칙을 호출처마다 다시 계산한 것이 이 갭의 원인이었으므로 두 번째 복사본을 만드는 대신 SSOT 를 세웠다. F-3 의 shadowing 경고도 `run_eval.warn_shadowing_skills()` 로 올라가 `run_loop` 이 반복 시작 전 1회(반복마다가 아니라 — shadowing 집합은 루프 도중 바뀌지 않는다) 출력한다. 집계 수치와 pass/fail 판정은 이전에도 정확했으므로 데이터 변화는 없고 표시·진단만 복구된다. `usable_runs` 키가 없는 #1412 이전 payload 는 `runs` 폴백을 유지한다 (#1428)**
