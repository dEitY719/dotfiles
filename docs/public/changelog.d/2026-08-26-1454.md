- 변경: **`dotfiles_root.sh` 에 비정본 `dotfiles` 체크아웃에서 sourced 된 것을 감지해 advisory WARN 을 찍는 `_dotfiles_root_warn_if_foreign_source` 가드를 추가하고 `gh_pr_review.sh` 에 적용한다 (issue #1454).** 디스크에는 `dotfiles` 라는 이름의 디렉터리가 4개 이상 있고 그중 하나는 몇 주 묵은 남의 submodule 체크아웃이다. Claude Code subagent 처럼 `$SHELL_COMMON` / `$DOTFILES_ROOT` 가 unset 인 비대화형 셸에서 공유 함수 파일을 탐색으로 고르면 그 낡은 사본이 정본 대신 sourced 되고, 증상은 원인과 아무 관계 없어 보이는 `Unknown --ai value: 'hermes'` 로 나타났다. 새 가드는 호출자가 넘긴 자기 자신의 `${BASH_SOURCE[0]-}` 만 신뢰한다 — `$SHELL_COMMON` 은 읽지 않는데, 틀린 `$SHELL_COMMON` 이 바로 감지 대상이므로 그 값으로 판정하면 판정 자체가 오염되기 때문이다. 판정은 `_resolve_dotfiles_root_canonical` 이 이미 쓰는 `git rev-parse --git-common-dir` 비교를 재사용해, load 경로와 `$HOME/dotfiles` 가 같은 `.git` 으로 수렴하면 침묵한다 — 따라서 **같은 저장소의 linked worktree 는 경고하지 않고**, submodule 체크아웃이나 별개 저장소만 경고한다. 절대 차단하지 않고 항상 0 을 반환한다: 다른 체크아웃을 의도적으로 시험하는 것은 정당한 사용이다. 인자 누락·파일 부재·`git` 부재·`$HOME/dotfiles` 부재는 전부 조용한 no-op 인데, 특히 마지막 경우를 경고로 만들면 격리된 `$HOME` 을 쓰는 테스트/샌드박스에서 매번 헛경고가 난다. 배선은 사고가 실제로 난 `gh_pr_review.sh` 한 곳뿐이며(나머지 전파는 후속 이슈), 이슈가 제시한 스니펫의 `2>/dev/null` 은 WARN 을 그대로 삼켜 기능을 무력화하므로 `command -v` 존재 검사로 바꿨다. 규칙 자체(비대화형에서 `find`/PATH 자가 발견 금지, 항상 `${SHELL_COMMON:-$HOME/dotfiles/shell-common}/...`)는 `docs/guide/playbooks/shell-common-cheatsheet.md` 의 Common Mistakes 7번으로 문서화했다. bats 10건 추가(20/20).
