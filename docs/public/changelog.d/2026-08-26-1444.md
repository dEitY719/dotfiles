- 변경: **토큰 한도 게이트(#1436)의 판정 입력을 `agent_prompt_stalled` 에서 "제출 확인 후 `working` 유지" 로 교체했다 (issue #1444).** 종전 판정은 `agent_prompt_stalled` + 비-`working` 상태를 한도 소진의 유일한 근거로 썼는데, #1443 이 같은 관측이 **claude 콜드 스타트 경쟁**에서도 그대로 나온다는 것을 실측으로 확인했다 — 입력창은 그려졌지만 키 루프가 Enter 를 아직 안 받는 구간이라 명령이 타이핑만 되고 제출되지 않는다. 두 원인이 바이트 단위로 동일한 관측을 만들므로 그 입력으로는 원리적으로 구분할 수 없었고(한도가 멀쩡해도 게이트가 30분 닫히는 오탐), 더구나 #1443 의 Enter 복구가 stall 을 되살리는 순간 그 판정은 **영원히 발동하지 않는 죽은 코드**가 된다. 새 판정은 행동 신호 2단계다. (1) 프롬프트가 실제로 제출됐는가 — `_iw_prompt_issue` 가 0 을 반환한 것이 그 증거다(herdr `--wait` 가 전이를 봤거나, Enter 복구가 `state_change_seq` 이동을 확인했거나). 제출이 확인되지 않은 실패는 입력 루프·전송 문제이지 한도 정보가 아니므로 게이트를 **손대지 않는다** — strike 도 clear 도 없다. (2) 제출이 확인된 디스패치를 `_IW_LIMIT_OBSERVE_SEC`(60초, 6회 폴링) 동안 관측해, `working` 에 못 들어가거나 창 안에서 `idle`/`done` 으로 되돌아오면 strike +1, 유지하면 clear 한다. `/gh-issue-flow` 한 건은 리뷰 게이트까지 수 분이 걸리므로, 제출이 확인된 작업이 60초 만에 조용해졌다면 일찍 끝난 게 아니라 시작되지 않은 것이다. `blocked` 는 `working` 과 함께 "살아 있음"으로 친다 — 사람을 기다리는 agent 는 한도가 남아 있다는 양성 증거다. 판정 단위도 디스패치별에서 **tick 단위**로 바뀌었다: 모든 pane 이 같은 `CLAUDE_CONFIG_DIR` 을 쓰므로(one account, one quota) 하나라도 `working` 을 유지하면 그 tick 전체가 무죄다. 이에 따라 루프 안의 `_iw_limit_gate_check || break` 는 제거됐다 — 관측이 사이클 뒤에 오므로 게이트가 사이클 중간에 닫힐 수 없다. strike 가 잡히면 `herdr agent read <agent> --lines 40 --format text` 로 pane 말미를 cron 로그에 증거로 남기지만, **문자열 매칭으로 게이트를 여닫지는 않는다** — claude 의 한도 배너 문구는 버전 종속이라 조용히 깨지고, 깨진 매칭은 fail-open 도 fail-closed 도 아닌 무증상 오작동이 된다. `_IW_LIMIT_STRIKES=2`, `_IW_LIMIT_BACKOFF_SECONDS=1800`, `rate-limit.json` 스키마, fail-open 원칙(NF-1), 시계·쓰기 실패 시 게이트 무시는 전부 그대로다. 판정에서 빠진 전역 `_IW_DISPATCH_ERROR_CODE` 는 제거하고 `_iw_prompt_issue` 의 지역 로그 변수로 낮췄다(`_IW_STALL_RECOVER_ERROR` 는 로그에서 "stall 처럼 보이는 pane 불통"을 구분하는 용도로만 남는다). bats 스텁에 `agent read` 와 프롬프트 이후 상태를 agent 별로 스테이징하는 `HERDR_STATUS_AFTER_PROMPT` / `HERDR_STATUS_AFTER_PROMPT_GETS` / `HERDR_WORKING_AGENTS` / `HERDR_READ_MODE` 를 추가했고, 게이트 테스트 절을 전면 교체했다 — 오탐 회귀 잠금(콜드 스타트 stall 은 strike 0), 미제출 실패 무판정, `working` 미진입 strike, 진입 후 이탈 strike, 유지 시 clear, 다건 디스패치에서 하나만 살아도 무죄, 증거 로깅, pane 문구가 게이트를 못 여는 것까지 156 케이스 전부 통과.
