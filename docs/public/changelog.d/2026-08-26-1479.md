- 변경: **`aicron` 의 `$$` 금지 가드 테스트(`no temp path is derived from the pid`)를 fail-closed 로 고쳤다 (#1479).** `grep` 은 패턴 불일치(1)와 파일 부재(2)를 모두 non-zero 로 내는데 `assert_failure` 는 둘을 구별하지 않으므로, 검사 대상인 `aicron.sh` / `lib/aicron_*.sh` 가 삭제되거나 옮겨져도 이 가드는 빨강이 아니라 초록이 됐다 — PR #1478 의 머지 후 차등 검증에서, 신규 테스트 72건을 PR 이전 트리에 얹었을 때 이 한 건만 "검사 대상이 없어서" 통과하며 실측됐다. B2(예측 가능한 임시 경로) 회귀를 막으려고 넣은 가드가 회귀와 파일 구조 변경이 함께 오는 시나리오에서 정확히 침묵하는 형태였다. 이제 grep 을 돌리기 전에 대상 목록의 모든 경로가 실재하는지 단언하고(글롭이 하나도 매치하지 않으면 셸이 리터럴 패턴을 남기므로 같은 `-f` 검사가 글롭 미매치까지 함께 잡는다), 종료 코드를 `assert_equal "$status" 1` 로 정확히 고정한다. 같은 grep 호출을 `$$` 가 심어진 픽스처에 돌려 0(일치)을 단언하는 양성 대조도 함께 둔다 — 1 이 "소스가 깨끗하다"는 뜻이지 "grep 이 눈이 멀었다"는 뜻이 아님을 테스트 스스로 증명해야 하기 때문이다. 검증은 차등으로 했다: lib 디렉터리를 치우면 종전 테스트는 통과했지만 지금은 실패하고, 실제 소스에 `$$` 를 심으면 여전히 실패하며, 손대지 않은 트리에서는 `aicron.bats` 72건이 그대로 통과한다. 수정 범위는 이 테스트 하나다 — 같은 클래스의 grep-종료코드 가드가 이 파일에 더 없음을 확인했다
