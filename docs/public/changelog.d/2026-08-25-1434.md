- 변경: **`gh:issue-flow` 의 early-stop 하네스 가드(`claude/hooks/gh_issue_flow_stop_guard.py`)를 `Stop` 뿐 아니라 `SubagentStop` 에도 등록했다. 서브에이전트의 턴 종료는 `Stop` 이 아니라 `SubagentStop` 으로 발화하므로, 서브에이전트 안에서 issue-flow 가 돌면 3중 가드 중 모델 협조가 필요 없는 유일한 레이어(하네스)가 통째로 빠져 있었다 — 남는 건 프롬프트 레이어 둘뿐이고, 이는 #333 / #383 / #1270 이 세 번 재발했던 바로 그 조건이다. 노출 경로가 issue-watcher 무인 dispatch(#1389)라는 점이 문제의 무게를 결정한다: 지켜보는 사람이 없어 체인이 중간에 잘려도 에러도 경고도 없이 리뷰·rebase 가 빠진 PR 만 남는다. 다만 단순 등록은 no-op 이었을 것이다 — 실제 `SubagentStop` payload 를 떠 보니(U-1) `transcript_path` 는 존재하지만 **부모 세션**의 transcript 를 가리키고 서브에이전트 자신의 transcript 는 별도 키 `agent_transcript_path` 에 담긴다(`Stop` payload 에는 `agent_*` 키가 아예 없다). 그대로 등록했다면 가드가 부모 transcript 를 파싱해 flow 경계를 못 찾고 fail-open — 설치된 것처럼 보이는 조용한 no-op 이 됐을 것이다. 그래서 훅에 transcript 해석 규칙을 넣어 `agent_transcript_path` 를 **우선** 쓰고 없을 때만 `transcript_path` 로 내려가며, 선택된 파일이 없으면 다른 키로 **폴백하지 않고** fail-open 한다(서브에이전트를 부모의 flow 상태로 판정하면 엉뚱한 block 이나 놓친 block 이 생긴다). 서브에이전트 transcript 의 JSONL 스키마는 부모와 동일해 경계 탐지 4갈래·L1.5 터미널 마커 스캔·stale boundary 만료 밸브·모든 fail-open 레일이 그대로 재사용되고, `stop_hook_active` 도 첫 발화 `False` / block 후 재발화 `True` 로 동일해 무한 루프 밸브가 유지된다. 가장 중요한 U-4 — `SubagentStop` 에서의 `{"decision":"block"}` 이 정말 서브에이전트를 계속 진행시키는가 — 는 추론이 아니라 실행으로 확인했다: `Stop hook feedback:\n<reason>` 이 **서브에이전트 자신의** user 채널에 주입되고 서브에이전트가 한 턴을 더 수행했으며, `Stop hook feedback:` 은 이미 `_HARNESS_INJECTION_RE` 에 있어 fresh-prompt 카운터도 오염되지 않는다. 회귀 방지로 추적 SSOT `claude/settings.json` 이 이 훅을 `SubagentStop` 에 배선했는지 검사하는 **등록 테스트**를 추가했다 — 애초의 갭을 잡아냈을 유일한 검사다. 같은 구조적 노출이 있는 `devx_autopilot_stop_guard.py` 는 이번 범위에서 의도적으로 미등록으로 남겼고(이번 결과를 보고 별도 판단), 잊히지 않도록 `references/stop-guard.md` 에 명시적 갭으로 기록했다. 배포 주의: 라이브 `~/.claude*/settings.json` 은 심볼릭 링크가 아니라 실파일이라 `git pull` 만으로는 새 훅이 닿지 않는다 — 사내(internal) 모드는 `session-start-settings-drift.sh` 가 매 SessionStart 자동 치유하고, 그 외 모드는 경고만 하므로 `claude/setup.sh` 재시딩이 필요하며 어느 쪽이든 **다음 세션**부터 적용된다 (#1434)**
