- 변경: **`issue_watcher_cron.sh` 의 중복 판정이 워크트리 존재 여부에서 GitHub 상태로 바뀌고, 동시 실행 상한과 워크트리 회수가 함께 들어왔다. 종전에는 신호 하나(`wt/issue-<n>` 워크트리가 있는가)가 유효 기간이 서로 다른 세 질문을 겸했다 — "지금 몇 건이 도는가"(작업 시작~종료), "이 이슈를 이미 처리했나"(처리 후 영구), "이 워크트리를 정리해도 되나"(종료 후). 워크트리는 dispatch 가 *시작*됐다는 사실만 알려주므로 셋 다 각각 다른 방향으로 틀렸다: `/gh-issue-flow` 는 PR 생성까지만 하고 머지는 사람 몫이라 머지 전에 워크트리를 지우면 이슈가 여전히 open 이므로 다음 tick 이 신규로 보고 같은 이슈에 PR 을 두 번 열었고, 안 지우면 리뷰가 밀리는 만큼 무한히 쌓였으며, dispatch 가 `--wait` 없는 fire-and-forget 이라 워크트리·pane 생성 후 claude 가 죽으면 tick 은 성공으로 간주하고 재시도(3회)도 발화하지 않은 채 **그 이슈가 다시는 후보가 되지 않았다** — 낭비가 아니라 조용한 유실이었다. 이제 질문마다 신호가 따로다: 실행 중 여부는 **herdr 의 살아있는 agent pane 이 그 이슈의 워크트리에 앉아 있는가**, 처리 완료 여부는 **그 이슈를 닫는 open PR 이 있는가**, 회수 가능 여부는 **이슈가 closed 이고 그 워크트리에 agent 가 없는가**로 답한다. `herdr agent list` 에는 agent 이름 필드가 없어(#1436 주석이 지적한 그 한계) `iw-<repo>-<n>` 을 이름으로 되찾을 수 없지만 각 pane 의 `cwd` 는 실려 오고 dispatch 된 pane 은 항상 이슈 워크트리 위에 열리므로, 그 컬럼을 `git worktree list` 의 `wt/issue-<n>/<index>` 브랜치 목록과 조인해 이슈 번호를 정확히 복원한다(디렉터리 이름 규칙에 의존하지 않는다). "이미 처리함" 판정은 저장소당 `gh pr list --state open` 한 번으로 받아 두 가지 표식을 본다 — 본문의 `Closes/Fixes/Resolves #<n>`(대소문자 무시, 단어 경계 포함이라 `Closes #115` 가 #11 을 은퇴시키지 않는다)와 head 브랜치 `wt/issue-<n>/*`. 각각 구멍이 있어서(손으로 연 PR 은 키워드가 없을 수 있고, 다른 이름의 브랜치에서 연 PR 은 브랜치 표식이 없다) 둘을 함께 쓴다. 이슈별 GraphQL 대신 저장소별 REST 를 쓰는 이유는 왕복 횟수와 GHES 호환성 둘 다다. 이 조회가 실패하면 그 저장소의 이슈를 이번 tick 후보에서 **제외**한다 — `blockedBy` 의 fail-open 과 방향이 반대인데, 오판의 대가가 비대칭이기 때문이다(조금 이르게 시작 vs 같은 이슈에 PR 2개). 상한은 셋으로 나뉜다: 전역 동시 실행 `7`(초과 시 dispatch 없이 `ux_info` 한 줄 남기고 `exit 0` — 기존 flock·게이트 skip 과 같은 취급), 저장소당 `3`(공평성 — 한 repo 가 나머지를 굶기지 않게), tick 당 투입 `1`(급증 시 7건이 토큰 집약 구간을 함께 지나가지 않게). 셋은 각각 누적량·공평성·투입 속도를 막으므로 하나로 대체되지 않는다 — 종전의 "사이클당 3건"은 투입 속도였을 뿐이고, dispatch 가 fire-and-forget 이라 정상 상태 동시 실행은 대략 `작업시간/tick주기 × 투입` 이었다(작업이 느려질수록 동시 실행이 늘어나는 구조). 그것이 폭주하지 않은 유일한 이유가 위의 "안 지우면 누적" 고장이었으므로, 회수 로직과 동시성 제어는 같은 변경에서 다뤄야 했다. tick 당 1건이므로 순서가 필요해졌다: 저장소는 라운드로빈(`select.json` 의 `last_repo` 로 지속, 파일이 없으면 첫 repo 부터 — 기존 상태 디렉터리는 그대로 동작한다), 저장소 안에서는 이슈 번호 오름차순이다. 워크트리 회수는 매 tick dispatch **전**에 돈다 — 확보한 자리를 같은 tick 에서 쓸 수 있고, 회수 실패가 dispatch 를 막지 않는다(경고 1줄 후 계속; 이제 워크트리 존재가 아무것도 결정하지 않으므로 회수는 위생 작업이지 정확성 요건이 아니다). `herdr agent list` 자체가 실패하면 동시 실행 수를 알 수 없으므로 dispatch 하지 않고 tick 을 끝낸다 — 모르는 채 던지면 herdr 이 불안정할 때 정확히 상한이 풀린다. `--dry-run` 은 여전히 아무것도 바꾸지 않는다(회수도 커서 전진도 하지 않으며, herdr 이 없으면 "도는 것 없음"으로 보고한다). 상한 3개는 `IW_MAX_PER_REPO`/`IW_MAX_CONCURRENT`/`IW_DISPATCH_PER_TICK` 로 덮어쓸 수 있다(기존 `IW_WATCHED_REPOS`/`IW_EXCLUDE_LABELS`/`IW_IDLE_POLL_SLEEP` 와 같은 모양). 기존 flock, 라벨 필터, `blockedBy` fail-open skip, 이슈당 3회 재시도, 한도 게이트(#1436), 이슈에 쓰기 전무 원칙은 그대로다. 운영 주기는 11분 권장(crontab 항목이며 스크립트 상수가 아니다).
