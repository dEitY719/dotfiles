- 변경: **`claude/hooks/plugin-sync.sh` / `claude/plugin/reconcile.sh` 가 만드는 매니페스트 sync 커밋의 제목이 대상 이름을 담는다 — 종전에는 `plugin install/uninstall`, `marketplace add/remove` 를 몇 번을 실행해도 커밋 제목이 항상 고정된 `chore(claude-plugin): sync manifest` 라 `git log --oneline` 만으로는 어떤 플러그인이 바뀌었는지 전혀 구분할 수 없었다. `plugin-sync.sh` 의 install/marketplace-add 경로에 (이미 uninstall 경로에 있던) `_extract_target` 호출을 추가해 단일 대상을 괄호로 붙인다(예: `... sync manifest (ralph-loop@claude-plugins-official)`) — 단, `claude/hooks/plugin-sync-session.sh` 가 세션 단위 재동기화를 트리거하려고 보내는 예약 문자열 `__slash_command_sync__` 는 실제 대상이 아니므로 그대로 통과시키지 않고 무이름 커밋으로 낮춘다. `reconcile.sh --apply` 는 단일 명령이 아니라 SSOT 전체 재계산이라 여러 항목이 한 번에 바뀔 수 있으므로, 새 `_changed_keys_marketplaces`/`_changed_keys_plugins`/`_build_sync_title` 가 실제 추가/삭제된 키를 `+`/`-` 접두어로 나열하고(`... sync manifest (+understand -ghost-mp ...)`), 4개를 넘으면 처음 3개 + `외 N개` 로 자른다. 이 변경은 `claude/plugin/publish-sync.sh` 의 `_ahead_commits_are_pure_sync` 와 정면으로 부딪힐 뻔했다 — 그 함수는 커밋 subject 를 `SYNC_MSG` 와 **정확히 문자열 일치**시켜 "이 커밋을 안전하게 rebase/collapse 해도 되는 순수 sync 커밋인지" 판정하고, 그 결과로 no-op 커밋 정리(`_collapse_stuck_sync_commits`)와 publish 후 로컬 main 정리(`_cleanup_local_main_if_pure_sync`)가 동작한다. 제목에 괄호가 붙으면 이 exact-match 는 항상 실패해 두 정리 로직이 에러 없이 조용히 멈추므로, 같은 함수를 "그대로거나 괄호 붙은 형태"만 인정하는 매칭(`case "$msg" in "$SYNC_MSG" | "$SYNC_MSG ("*")") ;; esac`)으로 바꿔 함께 고쳤다(단순 접두어 매칭은 우연히 같은 문자열로 시작하는 무관한 커밋까지 순수 sync 로 오인할 수 있어 괄호 형태까지 요구하도록 좁혔다, `/simplify` 리뷰). PR 제목(`_open_and_merge_pr` 의 `--title "$SYNC_MSG"`)은 여러 로컬 커밋을 하나의 snapshot 으로 합치는 batch publish 라 개별 이름을 담기 어려워 이번 범위에서 제외, 고정 형태 그대로 유지했다 (#1430)**
