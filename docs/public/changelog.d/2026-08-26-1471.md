- 변경: **단일 `docs/public/changelog.md` 를 PR 당 fragment 파일(`docs/public/changelog.d/<YYYY-MM-DD>-<issue>.md`)로 분해해 changelog 충돌 클래스를 구조적으로 제거했다.** 최근 main 30커밋 중 30건이 이 한 파일을 건드렸고 모두 같은 `## YYYY-MM-DD` 헤더 바로 아래 같은 줄에 삽입했다 — 충돌 확률이 1로 수렴하는 구조였고, 이미 산출물이 오염돼 `## 2026-08-13` 헤더가 두 개 뚫린 상태였다(my-share `report_range.py` 가 두 섹션을 각각 매치해 보고서에 같은 날짜 블록이 두 번 실렸다). `.gitattributes` 의 `merge=union` 은 채택하지 않았다 — 충돌은 사라지지만 항목 순서가 비결정적이 되고 배타적 편집도 조용히 양쪽 다 남기며, 무엇보다 "양쪽을 다 남긴" 것이 지금 오염의 원인이라 중복 헤더 클래스를 오히려 고착시킨다. fragment 방식은 **날짜를 파일명이 들고 있어 파일 안에 `##` 헤더가 아예 필요 없으므로** 중복 헤더가 재발 불가능하다. 기존 102개 항목을 텍스트 그대로 81개 fragment 로 분해했고(같은 날짜·같은 이슈는 한 파일에 여러 줄, 이슈 번호가 없는 레거시 9건은 `0000`), `changelog.md` 는 제거했다 — repo 안에서 이 파일을 읽는 코드가 0건이고 유일한 소비자가 my-share 라 파생물을 남기면 이중 진실이 되기 때문이다. 조립 경계는 소비자 쪽(`report_range.py`)에 둔다: main 룰셋의 `pull_request` rule 이 ACTIVE 라 조립 산출물을 커밋하려면 그 조립이 또 PR 을 요구하고 그 PR 이 다시 changelog 를 건드려 충돌 클래스가 부활하는데, 읽는 시점에 조립하면 조립 커밋 자체가 없어진다. my-share 수집기는 `changelog.md` 와 `changelog.d/` 를 합집합으로 읽으므로 나머지 6개 product 는 그대로 동작한다. 포맷 규칙이 산문에만 있고 강제 장치가 0건이었던 것이 중복 헤더가 뚫린 직접 원인이라, `scripts/lint_changelog_fragments.sh` 를 신설해 파일명·헤더 부재·빈 파일·불릿 형식을 FAIL 로 잡고 `mise run lint-docs` 에 연결했다. 동작 보존은 마이그레이션 전후 `report_range.py` 출력으로 검증했다 — 항목 102건·날짜 섹션 16개·섹션별 구성이 완전히 일치하고, 유일한 차이는 같은 날짜 안 순서가 "규칙 없음"에서 파일명 오름차순으로 결정론화된 것이다. 회귀 테스트 13건(FAIL 케이스마다 그 한 가지만 바꾼 양성 대조 포함)이 붙었다 (#1471)
