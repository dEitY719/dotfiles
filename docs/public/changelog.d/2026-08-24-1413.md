- 변경: **`./tests/test` 가 같은 호스트에서 동시에 도는 다른 `./tests/test` 실행을 감지해 CPU 잡 수를 나눠 쓴다 — 워크트리 여러 개가 동시에 전체 스위트를 돌릴 때 각 실행이 `nproc` 전부를 독점 요구하면서(bats 는 `xargs -P $(nproc)`, pytest 는 xdist `-n auto`) 20코어 머신의 load average 가 26~30 까지 치솟고 "병렬" 실행이 오히려 10분 넘게 걸리던 문제. `main()` 이 인자 파싱 직후(따라서 `-h/--help` 는 제외) `${TMPDIR:-/tmp}/dotfiles-tests-test-registry/` 에 자기 PID 이름의 빈 파일을 남기고, 읽는 쪽은 매번 `kill -0` 로 생존을 재확인한다 — 죽은 PID 항목은 무시되므로 크래시·강제 종료가 남긴 stale 파일이 있어도 자가 치유되고 trap 정리에 의존하지 않는다(`run_bats()` 가 자체 EXIT trap 을 해제하므로 애초에 의존할 수 없다; `main()` 의 정리 trap 은 tidiness 용도일 뿐이다). 유효 잡 수는 `max(1, base / (동시 실행 수 + 1))` 이고, bats 는 `xargs -P`, pytest 는 `PYTEST_XDIST_AUTO_NUM_WORKERS`(xdist 가 `-n auto` 를 해석할 때 보는 공식 knob — `pyproject.toml` 의 addopts 를 건드리지 않는다)로 각각 적용한다. 사용자가 명시한 `BATS_JOBS=N` / `PYTEST_XDIST_AUTO_NUM_WORKERS=N` 는 절대 스로틀하지 않는다. 스로틀이 걸리면 `Parallel: ... (throttled: N other ./tests/test run(s) detected)` 로 알린다. 함께 `pyproject.toml` 의 pytest 스케줄러를 `--dist load` → `--dist worksteal` 로 바꿨다 — 이 스위트는 빠른 유닛성 테스트와 느린 subprocess/pexpect 통합 테스트가 섞여 테스트별 소요가 크게 불균등한데, `load` 의 선분배 방식은 긴 straggler 뒤에서 다른 워커를 놀리는 반면 worksteal 은 유휴 워커가 대기 중인 테스트를 가져간다(pytest-xdist 3.8.0 에 이미 포함, 새 의존성 없음) (#1413)**
