- 변경: **`gh:pr-resolve-conflict` 도 `review-passed` 를 patch-id 로 재조정한다 — 충돌 없이 끝난 rebase 가 내용 동일이면 라벨을 유지하고 새 head 로 마커를 재발급한다(#1700 F-1, `gh:pr-resolve-outdated` 와 같은 헬퍼 공유)**
- 변경: **`review-passed` 재확인 조건을 "지금 라벨이 붙어 있나"에서 `review-verdict` 마커 존재로 바꿨다 — 먼저 라벨을 뗀 경로가 다른 경로의 재확인 자격까지 파괴하던 복구 불가 상태가 사라진다(#1700 F-2). 리뷰된 적 없는 PR 은 마커가 없어 여전히 라벨을 얻지 못한다**
- 변경: **`gh:pr-reply` Step 2.5 조기 종료(미답변 코멘트 0건)에서도 `review-passed` 게이트가 실행된다 — 이미 전부 답변된 PR 이 라벨을 재획득할 진입로가 생겼다(#1700 F-3, 빈 `ORIGINS` 로 이전 pass 이력만 보고 판단)**
- 변경: **재조정 진단 토큰이 patch-id 상태와 라벨 결과를 분리 보고한다 — `patch-id=<identical|changed|unreadable> label=<granted|dropped|failed>` (+ `prior=` / `marker=<reposted|failed|skipped>`). 내용이 동일한데 `patch-id=changed` 로 보고해 불필요한 재리뷰를 유도하던 오독을 없앤다(#1700 F-4)**
- 변경: **`review-blocked` 가 지금 붙어 있는 PR 은 patch-id 가 동일해도 `review-passed` 를 재부여받지 못한다 — 같은 head 에 나중에 내려진 블로커 판정이 예전 `review-passed` 마커를 지우지 않아, 마커만 보고 재부여하면 모순되는 두 판정이 공존하던 문제(PR #1703 리뷰, codex BLOCKER). 읽기 전용 확인이며 `review-blocked` 자체는 건드리지 않는다**
- 변경: **재조정 토큰이 "라벨 추가 실패"(`label=failed marker=skipped`)와 "마커 재게시 실패"(`label=granted marker=failed`)를 구분한다 — 라벨이 붙지 않았는데도 `label=granted` 로 보고하던 오보를 없앤다(PR #1703 리뷰, agy FOLLOW-UP)**
- 변경: **재조정 게이트에서 "조회 실패"를 "라벨 없음"으로 읽지 않는다** — `_gh_pr_resolve_outdated_has_label` 이 0(있음)/1(없음)/2(조회 실패) 3-상태를 돌려주고, `review-blocked` 가드는 1(확실히 없음)일 때만 통과한다. 이전에는 부정 조건이라 labels API 일시 장애가 "블로킹 없음"으로 읽혀 실제로 블로킹된 PR 에 `review-passed` 를 재부여할 수 있었다. drop 리포트에 `reason=` 필드가 추가된다.
- 변경: **답할 코멘트가 없는 pass 에서는 현재 head 를 지목한 리뷰 마커만 근거로 인정** — `_gh_pr_reply_history_has_review` 가 선택적 `[head-sha]` 를 받고, `ORIGINS` 가 비는 Step 2.5 경로에서만 이를 요구한다. 이전에는 sha 를 보지 않아, 리뷰 이후 head 가 전진한 PR 이 "언젠가 리뷰된 적 있음"만으로 아무도 본 적 없는 head 에 `review-passed` 를 받을 수 있었다.
