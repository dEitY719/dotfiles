- 변경: **`GH_HOST` pinning 계약이 남은 `gh:*` 스킬 13종에 전면 적용됐다 — `gh:pr-approve` · `gh:pr-merge` · `gh:pr-merge-emergency` · `gh:pr-reply` · `gh:pr-resolve-ci-fail` · `gh:pr-resolve-conflict` · `gh:pr-resolve-outdated` · `gh:pr-review` · `gh:relay-merge` · `gh:issue-proceed` · `gh:issue-relay-flow` · `gh:discussion-convert` · `gh:kanban-bootstrap`. PR #1404(#1403)가 계약을 도입했지만 적용 범위는 6종뿐이었고, 나머지 13종의 `gh` 호출 66건은 host 를 전혀 지정하지 않은 채 남아 있었다 — `--repo <owner>/<repo>` 슬러그는 host 를 담지 않으므로 `gh` 는 git 의 remote 가 아니라 자기 `gh repo set-default` 로 그 슬러그를 해석하고, github.com 과 GHES 두 곳에 동시 로그인한 PC 에서 **에러 없이 다른 서버로 나간다**. 그중 다수가 쓰기였다: `gh pr merge --admin --squash --delete-branch`, `gh pr review --approve` / `--request-changes`, `gh api -X DELETE .../labels/...`, `gh issue create`, `gh issue edit --add-assignee`. 각 스킬의 Step 1 이 `_gh_parse_owner_repo_url` + `_gh_host_from_url` 로 **하나의 remote URL** 에서 repo 와 host 를 함께 읽어 `export GH_HOST` 하고, 모든 호출이 `GH_HOST="$TARGET_HOST" gh ... --repo "$TARGET_REPO"` 형태가 된다. `--repo` 가 아예 없던 호출(`gh run list` · `gh run view` · `gh repo view --json defaultBranchRef` · `gh pr view --json labels` · `gh pr edit --add-label`)에는 `--repo` 를 함께 붙였고, `gh api` 는 `--repo` 플래그가 없으므로 리터럴 `{owner}/{repo}` · `<owner>/<repo>` placeholder 를 전부 `repos/$TARGET_REPO/...` 로 치환했다 — 그 placeholder 야말로 #1403 이 빠진 암묵 해석 경로다. 두 가지 예외는 의도된 것이다: (1) `gh:relay-merge` 는 host 를 넘나드는 것이 존재 이유라 전역 `GH_HOST` 를 export 하지 않고 `SOURCE_HOST`/`SOURCE_REPO` 와 `DEST_HOST`/`DEST_REPO` 두 쌍을 각자의 remote URL 에서 바인딩해 호출마다 인라인으로 붙인다. (2) 브랜치에서 PR 번호를 자동 탐지하는 `gh pr view`(인자 없음)는 `--repo` 를 주면 `gh` 가 PR 인자를 요구하며 거절하므로 host 접두사만 붙이고 그 이유를 인라인에 명시했다. 부수로 `gh:pr-resolve-ci-fail` 의 "`gh run view` 는 `--repo` 를 받지 않는다" 는 사실과 다른 주석(실제로는 `-R, --repo` 를 받는다)과 `gh:pr-resolve-conflict` 의 "`TARGET_REPO` 가 URL 일 수 있다" 는 낡은 근거를 함께 바로잡았다. 문서 복붙 계약이 다음 스킬에서 또 새지 않도록 신규 `scripts/maintenance/check_gh_skill_host_pinning.py` 가 `claude/skills/gh-*/**/*.md` 의 실행 가능한 `gh` 호출을 전수 스캔해 host 미고정과 repo 미고정을 잡고(backslash 연속 행은 논리 행으로 결합, `gh gist`/`gh auth` 등 repo 스코프가 아닌 서브커맨드는 예외), `tests/integration/test_gh_skill_host_pinning.py` 가 이를 실 트리에 대해 강제한다 — 수정 이전 트리에서 66건으로 실패하고 이후 통과하는 차등 검증을 거쳤다. 문장 중간에 인용된 `gh` 조각(예: "`gh pr view --json rebaseable` 은 Unknown JSON field 로 실패한다")은 실행이 아니라 설명이므로 의도적으로 스캔 대상에서 제외했고, 그 경계 자체를 테스트로 고정했다 (#1407)**
