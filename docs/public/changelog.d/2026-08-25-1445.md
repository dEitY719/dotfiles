- 변경: **`gh:issue-create` Step 4.5 의 `addBlockedBy` mutation 이 다시 동작한다. `AddBlockedByInput` 은 처음부터 단수 `blockingIssueId: ID!` 인데 기능을 넣은 커밋이 복수 배열 인자로 적어, mutation 은 한 번도 성공한 적이 없다 — 상류 스키마가 바뀐 게 아니라 실행해 보지 않은 인자 이름을 문서에 적은 것이 원인이다. NF-1(이슈는 이미 생성됐으므로 링크 실패는 중단 없이 경고 한 줄) 설계가 이 100% 재현되는 오작동을 권한·네트워크 같은 환경 오류와 똑같은 경고 한 줄로 흡수해, 그 사이 `Depends on #N` 을 적고 만든 이슈는 네이티브 링크 없이 생성됐다. 경고는 떴지만 매 `N` 마다 뜨는 평범한 링크 실패와 구분되지 않았고, GH UI 사이드바에 `Blocked by` 가 안 뜨는 것으로만 확인됐다. 읽기 경로(`Issue.blockedBy` 조회)는 처음부터 멀쩡했으므로 issue-watcher 디스패처의 선행-이슈 확인과 `gh:issue-implement`/`gh:issue-proceed` 의 본문 grep 은 영향이 없었고, 깨진 것은 쓰기 경로뿐이다. 이번 수정으로 mutation 인자를 `blockingIssueId` 로 교정하고, 라이브 스키마 introspection 으로 확인한 인자 형태를 `references/dependency-detect.md` 의 가용성 서술 옆에 명시했다 — 종전에는 "github.com / GHES 3.19+ 에서 쓸 수 있다"만 적혀 있어 인자 이름을 대조할 기준 자체가 없었다. 다만 이 기록은 검증된 기준일 뿐 자동 검출 장치가 아니다: 문서와 실제 스키마를 비교하는 것은 여전히 사람 몫이다. 단수 인자이므로 mutation 을 배칭한다는 선택지가 없어졌고, 존재하지 않는 대안과의 트레이드오프를 설명하던 문단은 삭제했다 — per-`N` mutation 이 유지되는 이유는 이제 "스키마가 그것만 허용해서"이고 NF-1 의 per-`N` 경고 약속은 그 결과로 자연히 지켜진다. GraphQL 호출 자체는 목킹하면 목을 테스트하게 되므로 자동 테스트를 만들지 않는 기존 판단을 유지하되, 스키마 introspection 과 실제 링크 사례(#1444 가 #1440·#1443 두 건에 링크됨)로 실 API 검증을 대신했다. 그 사이 링크가 누락된 기존 이슈의 소급 백필은 하지 않는다 — 본문 트레일러 기반 기능적 차단은 이미 동작 중이고 잃는 것은 사이드바 표시뿐이라, 필요한 건만 사람이 GH UI 에서 추가한다 (#1445)**
