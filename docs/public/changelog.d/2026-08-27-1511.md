- 변경: **`gh:pr-merge` 가 머지를 끝낸 뒤, `docs/.ssot/watched-repos.json` 에 등록된 저장소에 한해 새 아톰 스킬 `gh:pr-post-merge-verify` 로 검증 세션을 자동 디스패치한다. 종전에는 머지 후 사람이 매번 여섯 단계를 손으로 반복했다 — 구현 herdr 탭을 닫고, 원본 체크아웃(워크트리가 아니라)에서 `fetch`+`rebase` 하고, herdr 탭을 새로 열고, 그 안에서 claude 세션을 띄우고, `/devx-pr-verify-merged <N>` 를 타이핑하는 순서다. 이제 그 순서가 한 스킬 안에 있다: 머지된 head 브랜치 → `git worktree list` 로 로컬 워크트리 경로 → `herdr agent list` 의 `cwd`/`foreground_cwd` prefix 매칭으로 그 워크트리에 앉은 `tab_id` 를 찾아 `herdr tab close`, 원본 체크아웃에서 `fetch origin main && rebase origin/main`, `herdr tab create --label pr-<N>`, `herdr agent start pmv-<host>-<owner>-<repo>-<N> --kind claude -- --dangerously-skip-permissions`, `herdr agent prompt <agent> "/<verify_skill> <N>" --wait --until idle`, 그리고 새 tab id·agent 이름·`herdr agent attach` 힌트 보고. 옵트인이 이 기능의 전부다 — 등록되지 않은 저장소는 `[INFO]` 한 줄조차 없이 #1511 이전과 바이트 단위로 동일하게 동작하고, `herdr` 이 없으면 스킬 전체가 조용히 no-op 이며, 레지스트리 파싱이 깨지면 `[WARN]` 한 줄 뒤 기능만 건너뛴다. 저장소별 `verify_skill` 은 `devx:pr-verify-merged` 와 `devx:pr-verify-live` 중 하나이고 둘의 차이가 rebase 의 성격을 바꾼다: `-merged` 는 머지 커밋을 스스로 fresh clone 하므로 rebase 는 위생 작업이지만, `-live` 는 돌아가는 앱의 서빙 체크아웃 자체가 증거이므로 rebase 는 진짜 전제 조건이다. 그래서 원본 체크아웃이 dirty 하거나 rebase 가 충돌하면 그것만 hard stop 이다 — `[WARN]` 후 `rebase --abort` 로 체크아웃을 되돌리기만 하고(충돌 해결은 사람 몫) 새 탭을 열지 않는다. 오래된 코드를 검증하면 통과가 곧 오답이기 때문이다. 나머지 실패(구현 탭 없음·`tab close` 실패·`tab create` 실패·`agent start` 실패·프롬프트 실패)는 전부 soft-fail 이라 `gh:pr-merge` 의 리포트는 언제나 그대로 출력된다. agent 이름에 host 가 들어가는 이유는 `pr_merge_train_cron.sh` 의 `_PMT_AGENT_PREFIX` 와 같다 — `owner/repo` 만으로는 GitHub 서버가 다르면 유일하지 않아 #1403/#1407 의 host pinning 이 세션 식별 계층에서 무너진다. `herdr agent list` 가 아무것도 답하지 않는 경우는 "도는 게 없음"이 아니라 "모름"으로 취급하고(issue_watcher_cron.sh 의 교훈), 빈 경로 prefix 는 모든 agent 에 매치돼 엉뚱한 탭을 닫으므로 아예 거부한다. 탭 생성 응답의 pane 은 경로가 아니라 leaf 키 이름으로 스캔해
