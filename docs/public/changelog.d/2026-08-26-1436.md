- 변경: **`issue_watcher_cron.sh` 의 `_iw_prompt_issue` 가 `agent_prompt_stalled` 를 재타이핑이 아니라 Enter 전송으로 복구한다 (issue #1443, #1440 아키텍처 위에 갱신).** `agent_prompt_stalled` 는 herdr 가 pane 에 명령을 *쳐 넣었으나* 5초 창 안에 상태 변화를 못 봤다는 뜻이다 — 즉 `/gh-issue-flow <N>` 텍스트는 이미 입력창에 미제출 상태로 앉아 있고, 키 입력 루프가 아직 Enter 를 받지 않았을 뿐이다. 종전 복구는 같은 명령을 `herdr agent prompt` 로 한 번 더 보냈는데, 이건 입력창의 기존 텍스트 위에 명령을 겹쳐 쳐서 줄을 망가뜨릴 뿐 Enter 는 여전히 눌리지 않는다. 이제 복구는 `herdr agent send-keys <agent> Enter` 다 — 빠진 키 하나를 보낼 뿐, 프롬프트는 tick 당 정확히 한 번만 나간다(bats 가 `agent prompt` 호출 수 1 로 못박는다). 제출 성공 판정은 `agent_status` 가 아니라 `herdr agent get` 의 `state_change_seq` 로 한다: `idle` 은 "입력 대기 중"과 "입력창은 그렸지만 키 루프가 아직 안 붙었음"을 구분하지 못하고, 그 모호성이 #1443 의 근인이기 때문이다. 기준값(`_seq0`)은 stall 을 감지한 뒤가 아니라 프롬프트를 보내기 *전에* 잡는다 — 사후에 잡으면 감지하려던 그 제출로 이미 카운터가 움직인 뒤라 구분이 불가능하다. Enter 는 최대 3회, 2초 간격(`_IW_STALL_RECOVER_ATTEMPTS` / `IW_STALL_RECOVER_SLEEP` 로 조정, 후자는 `IW_IDLE_POLL_SLEEP` 과 같은 관례)이며, 카운터가 움직이는 즉시 중단한다. 기존의 "이미 `working` 이면 복구 생략"(#1400) 단락 판정은 그대로다 — 프롬프트가 이미 안착했다는 양성 증거이므로 보낼 키가 없다. PR #1449 codex 리뷰가 짚은 두 blocker 도 함께 반영했다. (A) 기준값을 읽는 `agent get` 자체가 일시적으로 실패하면 `_seq0` 이 비고, 이후 순번 비교는 Enter 가 실제로 안착해도 영원히 성립하지 못해 일회성 blip 이 영구 실패로 승격된다 — `_seq0` 이 비었을 때는 회차마다 `agent_status == "working"` 을 대신 보는 것으로 대체한다(기존 단락 판정이 이미 신뢰하는 것과 동일한 증거). (B) `send-keys` 가 그 자체로 실패하면(agent 소멸, pane 종료, herdr 불통) 이는 "아직 변화 없음"과 다른 사건이므로 남은 회차를 죽은 대상에 낭비하지 않고 즉시 중단하고, 신설 `_IW_STALL_RECOVER_ERROR="herdr_send_keys_failed"` 를 `_IW_DISPATCH_ERROR_CODE` 로 올린다 — 이걸 안 하면 프롬프트 응답의 `agent_prompt_stalled` 가 그대로 남아 토큰 한도 게이트(#1436)가 깨진 pane 하나 때문에 30분간 디스패치를 닫는다. `_iw_limit_record` 는 손대지 않았다: 코드가 달라지는 순간 기존 "not a token-limit signature" 분기가 알아서 올바르게 동작한다. 해소되지 않은 평범한 stall 은 종전대로 `agent_prompt_stalled` 를 보고하므로 게이트의 strike 누적 동작은 불변이다. bats 스텁에 `state_change_seq` 카운터와 `agent send-keys` 케이스(`HERDR_SENDKEYS_MODE`: `ok`/`nobump`/`fail`, 기본 `nobump` — 기존 stall 테스트의 의미를 그대로 보존)를 추가했고, 회귀 테스트 7건이 붙어 총 105건이 통과한다.
