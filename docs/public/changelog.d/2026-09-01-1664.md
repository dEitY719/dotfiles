- 변경: **`git/setup.sh` 가 `~/.config/git/hooks` 에 `pre-commit` 하나만 링크해 `pre-push`·`commit-msg`·`prepare-commit-msg`·`post-commit` 이 전 PC 에서 죽어 있던 문제를 고쳤다 — `core.hooksPath` 는 `.git/hooks` 를 병합·폴백 없이 대체하므로 글로벌 디렉터리에 없는 hook 은 아예 실행되지 않는다. `mise run test` 로컬 테스트 게이트(#754), 보호 브랜치 차단, upstream leak guard 가 다시 작동한다 (#1664)**
- 변경: **`git/global-hooks/` 에 `pre-push`·`commit-msg`·`prepare-commit-msg`·`post-commit` 위임 wrapper 를 추가했다 — `pre-commit` wrapper 와 동일하게 현재 작업 중인 레포 기준으로 `.githooks/<name>` → `git/hooks/<name>` → `.git/hooks/<name>` 를 찾아 argv·stdin·종료코드를 그대로 넘기고, 해당 hook 이 없는 레포에서는 조용히 no-op 한다. `git/hooks/*` 를 글로벌 디렉터리에 직접 링크하면 dotfiles 전용 로직이 머신의 모든 레포에서 실행되므로 금지다**
- 변경: **hook 세트 SSOT 를 `git/config/hook-config.sh` 의 `GIT_GLOBAL_HOOKS` 배열로 두고 `git/setup.sh` 와 `hook-check` 진단이 함께 참조한다 — `hook-check` 는 이제 5개 hook 전부의 존재·실행권한·깨진 symlink·문법을 검사한다(기존에는 `pre-commit` 만)**
- 변경: **`git/setup.sh` 가 글로벌 hook 디렉터리의 기존 실파일을 교체할 때 경고를 출력한다 — git-lfs 가 설치한 `pre-push`/`post-commit` 이 `<name>.original` 로 백업되므로 교체 후 `git lfs install --force` 재설치가 필요하다**
