(2) `_iw_limit_gate_check` 를 재사용하지 않는다 — 그 함수는 판정의 일부로 만료된 `rate-limit.json` 을 *삭제*하므로, 재사용하면 조회 명령이 상태를 바꾸게 된다(`--dry-run` 이 같은 이유로 게이트 평가를 피한다, PR #1447). 만료 판정 산술은 두 리더가 공유하는 순수 분류기 `_iw_limit_gate_state` 하나로 뽑아 "자기 길이의 2배보다 먼 마감은 시계 점프" 이상치 가드까지 한 곳에만 두었다 — 산술은 공유하되 공유하면 안 되는 부작용(만료 파일 삭제)은 그럴 자격이 있는 호출자(tick)에만 남으므로, 게이트 규칙을 다음에 손봐도 `--status` 가 실제 tick 동작과 어긋날 수 없다(PR #1469 codex 리뷰). (3) `gh` / `herdr` 존재 검사보다 앞에서 응답한다 — 게이트는 로컬 state 파일이므로, 진짜 tick 이 아예 못 도는 환경에서도 답이 나와야 한다. 종료 코드는 항상 0 이다: 닫힌 게이트는 오류가 아니라 정상 운영 상태이고, cron 래퍼가 `set -e` 로 죽으면 안 된다 — 상태는 텍스트가 전달한다. bats 10건 추가(159/159). 함께 bats graphql 스텁의 stdin drain 을 tty 에서 건너뛰도록 고쳤다(`[ -t 0 ] || cat`) — 인터랙티브 셸에서 리디렉션 없이 스위트를 돌리면 tick 의 stdin 이 tty 에 남아 키보드를 영원히 기다렸고, 실패한 테스트 하나 없이 멈춘 것처럼 보였다(PR #1469 agy 리뷰).
