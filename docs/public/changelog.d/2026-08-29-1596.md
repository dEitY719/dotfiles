- 변경: **issue-watcher 의 "running now" 신호가 pane 의 `agent_status` 를 함께 본다 — `agent_status` 가 `idle`/`done` 이면서 해당 이슈가 GitHub 에서 이미 CLOSED 인 pane 은 live 집합에서 제외된다. 지금까지는 pane 의 `cwd` 가 이슈 워크트리 안에 있기만 하면 무조건 live 로 셌기 때문에, 머지 후 닫히지 못한 herdr 탭(좀비 탭)이 repo 당 동시 실행 상한(`_IW_MAX_PER_REPO`, 기본 7)의 슬롯을 영구히 점유해 해당 repo 의 신규 이슈 dispatch 가 조용히 멈추고, 그 워크트리도 영영 회수되지 않았다. 두 조건을 모두 요구하는 이유는 각각이 정상 중간 상태이기 때문이다 — 에이전트는 툴 호출 사이에 잠깐 `idle` 이 되고, 이슈는 세션이 머지 검증 중일 때 이미 닫혀 있을 수 있다. `idle`/`done` 이 아닌 상태(미지의 상태 포함)와 이슈 상태 조회 실패는 모두 "아직 살아 있음" 쪽으로 판정한다. `gh issue view` 왕복은 멈춘 pane 에 대해서만 지불한다. (#1596)**
- 변경: **좀비 pane 판정에 유예 기간(grace period)이 붙었다 — `idle`/`done` + 이슈 CLOSED 조건이 한 tick 이 아니라 `IW_ZOMBIE_GRACE_SECONDS`(기본 600초) 이상 떨어진 두 번의 관측에서 연속으로 관찰돼야 pane 을 죽은 것으로 확정한다. 백그라운드 서브에이전트에 작업을 위임하고 결과를 기다리는 에이전트는 수 분 동안 `agent_status: idle` 로 보고하는데, 단일 스냅샷으로는 이 대기와 진짜 종료를 구분할 수 없어 실행 중인 세션의 슬롯을 회수(중복 dispatch)하거나 워크트리를 통째로 제거할 위험이 있었다. 유예 시계는 상태 디렉터리의 `zombie-candidates.tsv` 에 `<repo>\t<번호>\t<최초 관측 epoch>` 로 기록되며, pane 이 다시 `working` 으로 돌아오거나 이슈가 열려 있으면 즉시 삭제돼 다음에 조용해질 때 시계가 처음부터 다시 시작한다. (#1596)**
