- 변경: **WSL 에서 링크를 여는 세 경로(`$BROWSER` · `xdg-open` · `x-www-browser`)가 모두 Windows 쪽 Chrome 하나로 모인다. 신규 `shell-common/env/browser.sh` 가 셸 시작 시 `$BROWSER` 를 export 하는데, 값은 chrome.exe 경로가 아니라 신규 래퍼 `shell-common/tools/custom/open_in_windows_chrome.sh` 의 경로다 — `$BROWSER` 는 단순 경로가 아니라 명령 스펙이라 Python `webbrowser`(`shlex.split`) · `sensible-browser` 등 소비자가 단어 분리를 하는데, 기본 설치 경로 `/mnt/c/Program Files/...` 의 공백 때문에 `/mnt/c/Program` 을 실행하려 들기 때문이다. 래퍼는 인자를 chrome.exe 로 넘기되 WSL 로컬 경로와 `file://` URL 은 `wslpath -w` 로 Windows 경로로 변환하고(존재하지 않는 경로 · `https://` URL · Chrome 플래그는 그대로 통과, `%20`/`%25` 만 디코드), WSL(`/proc/version` 에 `microsoft`)이 아니거나 Windows 에 Chrome 이 없으면 아무것도 export 하지 않는 완전 no-op 이라 macOS/순수 Linux 에는 영향이 없다. 머신별로 다른 브라우저를 쓰려면 `shell-common/env/browser.local.sh` 에 덮어쓰면 된다(`proxy.local.sh` 와 같은 관례, 기본값 이후에 로드된다). chrome.exe 탐색 규칙은 신규 `shell-common/functions/windows_chrome.sh` 한 곳에만 있고 (`Program Files` → `Program Files (x86)` → 사용자별 `AppData` 순, `WINDOWS_CHROME_EXE` 로 명시 지정 가능 / `WINDOWS_CHROME_DRIVE` 로 C: 마운트 위치 변경 가능), 세 경로가 같은 실행 파일을 가리키는 것은 이 SSOT 를 공유하기 때문이다. `xdg-open` 과 `x-www-browser` 는 저장소가 아니라 머신 로컬 상태(`~/.local/share/applications/windows-chrome.desktop`, `~/.config/mimeapps.list`, `update-alternatives`)라서 자동 적용하지 않는다 — 명시적으로 `shell-common/tools/custom/open_in_windows_chrome.sh --register` 를 실행해야 하고 (`--dry-run` 으로 무엇이 바뀌는지 먼저 확인), `setup.sh` 에는 연결하지 않았다. `--register` 는 절대 경로를 `.desktop` 과 `update-alternatives` 에 박아 넣으므로 linked git worktree 에서 실행하면 거부하고 메인 체크아웃 경로를 알려준다. root 가 필요한 `update-alternatives` 단계는 비밀번호 없는 sudo 일 때만 자동 실행하고 그렇지 않으면 실행할 두 줄을 출력만 한다.
