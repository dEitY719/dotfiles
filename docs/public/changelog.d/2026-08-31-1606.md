- 변경: **`issue-watcher` 가 동시 실행 슬롯이 오래 포화된 상태를 스스로 알린다 — 캡이 꽉 차서 아무것도 디스패치하지 못한 tick 이 `IW_SATURATION_ALERT_TICKS`(기본 20, `*/3` 크론 기준 약 1시간) 연속으로 이어지면 `herdr notification show` 로 정확히 한 번 알림을 보낸다.** 알림 본문에는 현재 슬롯을 점유한 이슈 번호와 각각의 `agent_status` 가 `<repo>#<number>: <status>` 한 줄씩 실린다 — 진짜로 바쁜 세션과 닫히지 않은 좀비 탭을 pane 에 일일이 붙어보지 않고 구분하기 위해서다. 원인은 일부러 따지지 않는다: 슬롯이 밤새 막힌 사고가 서로 무관한 두 원인(#1596/#1597 좀비 탭, #1604 쿼터 백오프 미재개)으로 이미 두 번 있었고 둘 다 다음 날 아침 사람이 물어보고서야 발견됐으며, 원인 분류는 #1444 에서 rate-limit 게이트가 거부한 pane 텍스트 매칭을 다시 들여오는 일이기 때문이다. 상태는 `${XDG_STATE_HOME:-$HOME/.local/state}/issue-watcher/saturation.json` (`{ "ticks", "last_notified" }`) 에 남고, 알림 후에는 `IW_SATURATION_COOLDOWN_SECONDS`(기본 10800 = 3h) 동안 같은 에피소드에 대해 다시 보내지 않는다(카운터는 계속 증가하며, 쿨다운은 *알림*만 막는다). 실제 디스패치가 한 번이라도 일어나면 상태 파일을 지워 다음 포화는 새 사건으로 취급하고, 후보 이슈 자체가 없는 tick 은 포화 근거도 해소 근거도 아니므로 카운터를 그대로 둔다. herdr 가 알림을 거부하면 쿨다운을 시작하지 않고 다음 tick 에서 다시 시도한다 — 실패한 알림에 쿨다운을 찍는 것은 경고 한 줄을 3시간의 침묵과 맞바꾸는 일이기 때문이다. 상태 파일 I/O 실패는 경고 한 줄만 남기고 tick 을 막지 않는다(NF-1) (#1606)
