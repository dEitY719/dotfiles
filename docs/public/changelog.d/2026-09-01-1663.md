- 변경: **`gcp scan` 의 config 오염 방어가 `alias cp='cp -i'` 를 켠 인터랙티브 zsh 에서 무력화되던 결함을 고쳤다 (#1663)** — zsh 는 alias 를 parse 시점에 확장하므로 `zsh/main.zsh` 의 Phase 4(aliases) → Phase 5(functions) 순서에서 `gcp_scan.sh` 함수 본문에 `cp -i` 가 영구 각인됐고, 복원 `cp` 가 비-TTY stdin 에서 덮어쓰기 확인을 못 받아 조용히 실패해 오염된 `git/.gitconfig` 가 복구되지 않았다. `[include]` 토폴로지(setup-mode `internal`)에서는 이후 모든 git 명령이 죽어 수동 복구가 필요했다.
- 변경: **`shell-common/functions/gcp_scan.sh` 의 스냅샷/복원 호출 11곳을 `command cp` / `command rm` 으로 전환했다** — `command` 는 대상 단어를 인자 위치에 놓아 zsh 가 alias 확장을 하지 않으므로, **전환된 이 호출 지점들은** 누가 어떤 순서로 `cp`/`rm` alias 를 켜고 소싱하든 면역이다. 파일 전체가 면역이 되는 것은 아니다 — `git`/`mktemp`/`awk` 등 접두사 없는 다른 명령어는 여전히 parse 시점 alias 확장 대상이며, 이번 범위는 config 오염 경로에 한정한다. 전역 옵션을 건드리는 `setopt no_aliases` 래핑(#1149 의 과거 fix)은 복원 스킵 회귀 위험 때문에 채택하지 않았다.
