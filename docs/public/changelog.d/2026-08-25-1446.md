- 변경: **`gh:issue-create` 가 미결이 남은 초안으로는 이슈를 만들지 않는다. Step 3(본문 초안)과 Step 3.5 사이에 **Step 3.1 미결 게이트**를 신설했다 — 초안에 (a) 비어 있지 않은 `## Open Questions` 섹션, (b) "구현 시 결정" / "추후 결정" / "논의 필요" / "TBD" / "미정" 류 표현, (c) 임계값·경로·형식이 비었거나 "적절히" / "필요 시" 로만 서술돼 판정 불가능한 판정 기준 — `feat` 의 `수용 기준` 뿐 아니라 `fix`/`perf`/`refactor`/`test` 의 `## 검증`, `verify` 의 `## Verification Goal` 까지, 체크박스든 평범한 불릿이든 — 중 하나라도 있으면, 항목별로 **권고안과 근거**를 제시하고 사용자 응답 전에는 `gh issue create` 를 호출하지 않는다. (c) 기준이 필요한 이유는 #1436 이 보여줬다 — `Open Questions` 섹션 밖 설계 본문에 미결이 흩어져 있으면 (a)·(b) 만으로는 못 잡는다. 게이트를 Step 2.1(Clarification & Scope Guard)에 합치지 않은 것은 Step 2.1 이 초안 작성 *전*이라 무엇이 미결인지 알 수 없기 때문이다. 확정 결과는 본문 `## 확정 사항 (Decisions)` 에 `<결정> — 근거: <한 줄>` 로 남아, 나중에 사용자가 뒤집을 근거가 이슈 안에 남는다. `feat` 템플릿의 `## Open Questions` 는 `## 확정 사항 (Decisions)` 으로 교체됐다(템플릿 중 유일한 보유처). 무인 호출용으로 `--no-ask` 를 추가했다 — 묻는 대신 (1) 저장소 관례·상수·인접 구현에서 유추, (2) 없으면 가장 보수적인 쪽, (3) 둘 다 불가능하면 그 항목만 수용 기준에서 빼고 별도 이슈 대상임을 명시, 순으로 스스로 정하고 `(자율 판단)` 표기와 근거를 남긴 뒤 진행하므로 체인이 멈추지 않는다. `devx:autopilot` Step 0b 가 이 플래그를 넘긴다. `--as-discussion`(`DISCUSSION_MODE=1`)은 게이트를 통째로 건너뛴다 — RFC 는 미결이 산출물의 본질이다. `미정` 만은 토큰 경계를 요구한다 — 부분 문자열로 잡으면 "김미정"(인명) · "장미정원" · "범위 미정의"(Step 2.1 어휘)가 오탐되는데, 이 게이트의 오탐 비용은 이슈 생성 차단이라 누락보다 비싸다. 사용자가 "그냥 만들어" 로 답하면 통과시키되 미결을 `(보류 — 사용자 지시)` 로 기록하고, 일부만 답하면 남은 항목만 다시 묻는다(임의 보완 금지). 미결이 없으면 게이트는 아무 출력도 내지 않는다. 이 게이트가 필요한 이유는 이 저장소의 이슈가 사람만 읽는 문서가 아니라 `gh:issue-flow` / `devx:autopilot` / `gh:issue-proceed` 의 **무인 실행 입력**이기 때문이다 — 셋 다 실행 중 사람에게 물을 채널이 없어, 미결이 남으면 그 지점에서 멈추거나 근거 없이 추측해 진행하고 나중에 되돌린다 (#1446)**
