- 변경: **`issue_watcher_cron.sh` tick 이 감시·디스패치 1~7단계를 직접 수행한다 — 상주 claude 세션과 그 안의 dispatcher 서브에이전트 층이 사라졌다. 종전에는 tick 이 전용 herdr workspace 의 `iw-watch` pane 에 "issue-watcher:dispatcher 를 Agent 도구로 실행해" 라는 한국어/영어 산문을 보내고, 그 세션이 개인 파일 `profile.md` 의 7단계를 매 tick 해석해 조회·필터·워크트리·pane 생성을 수행했다. 그 7단계에는 판단이 한 번도 없다 — 조건 분기와 외부 명령 호출뿐인데, 무인 5분 주기 경로의 절반이 테스트 0줄의 산문이었고 비결정성이 장점이 아니라 부채였다. 이제 tick 이 `gh search issues --assignee @me --state open` 한 번으로 교차 저장소를 조회하고(저장소별 `gh issue list` 순회가 사라진다), 제외 라벨(`wontfix`/`보류`/`not-implement`, 정확 일치)·watched-repos.json 소속·워크트리 존재·`blockedBy` OPEN 순으로 거른 뒤 이슈마다 워크트리 + herdr tab(`#<N>`) + claude agent(`iw-<N>`)를 만들고 `/gh-issue-flow <N>` 을 보낸다. LLM 판단은 그 슬래시 명령 한 곳에만 남는다. 필터 순서는 비용순이다 — 네트워크를 타는 `blockedBy` 조회는 로컬 검사를 모두 통과한 이슈만 본다. 동작은 보존된다: 사이클당 3건 상한, 이슈당 3회 재시도, 재시도 전 `gwt remove --force` 로 잔존 워크트리 정리, 중복 판정은 현행 기준(워크트리 존재)을 그대로 옮겼다(PR 상태 기반 전환은 동작 변경이라 AgentToolbox #2848 C5 로 분리). 이슈에 대한 쓰기는 여전히 전무하다 — bats 의 `gh` 스텁이 `search issues` 와 `api graphql` 외 모든 서브커맨드를 거부하므로 이건 주장이 아니라 테스트다. 이관의 부수 효과로 세 가지가 없어졌다: `_IW_PROMPT`/`_IW_TIMEOUT_MS` 짝의 프롬프트 모호성(#1394 의 발생 조건 자체), `/gh-issue-flow` 가 서브에이전트 안에서 돌아 `SubagentStop` 가드 공백에 노출되던 경로(#1434 — 이제 톱레벨), 그리고 상태 파일 `herdr-watch.json` 전체(workspace 는 herdr 서버에서 label 로 조회하면 되므로 영속 상태가 필요 없다). tick 겹침 방지는 상주 agent 의 `idle`/`working` 상태 대신 기존 flock 단독으로 간다. 토큰 한도 게이트(#1436)는 그대로 살아 있고 관측 대상만 바뀌었다 — 종전에는 `iw-<n>` pane 을 주소 지정할 수 없어 한 단계 위 `iw-watch` 를 대신 봤는데, 이제 tick 이 agent 이름을 스스로 정하므로 실제 dispatch 를 직접 본다. 게이트가 서 있던 "모든 pane 이 한 계정/한 쿼터" 전제는 `_iw_resolve_config_dir` 이 tick 당 한 번 해석해 모든 tab 에 같은 `CLAUDE_CONFIG_DIR` 을 싣는 것으로 그대로 유지된다. 신규 `--dry-run` 은 후보 목록만 출력하고 아무것도 만들지 않으며 herdr 없이도 돈다 — 이슈가 요구한 이관 전후 대조 절차의 도구다. 조회·필터가 객체 배열을 다루므로 `jq` 는 이 경로에서 선택이 아니다: 없으면 반쯤 파싱된 후보로 디스패치하는 대신 큰 소리로 거절한다. `watched-repos.json` 은 감시 목록이 아니라 결과 필터 + 로컬 경로 매핑으로만 쓰이고(`[{repo, path, host}]` 와 `{repos:[...]}` 두 형태 허용, `$IW_WATCHED_REPOS` 로 override), 이관 원본인 avatar `profile.md` 는 본 저장소 밖 개인 파일이라 정리 결과는 이슈 코멘트로 기록한다. bats 하네스는 879줄에서 85케이스로 다시 짜여 실제 git 저장소에 진짜 워크트리를 만들며 중복 판정을 검증한다 (#1440)**
